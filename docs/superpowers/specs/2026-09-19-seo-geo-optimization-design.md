# SEO + GEO optimization — design

Date: 2026-09-19. Site: https://mariusmircioaga.com (Create React App, prerendered by `scripts/prerender.mjs`, hosted on Vercel behind Cloudflare).

## Goal

Make every page of the portfolio maximally legible to search engines (Google, Bing) and to AI answer engines (Google AI Overviews / AI Mode, ChatGPT search, Perplexity, Claude, Copilot), without changing the visual design or the author's voice.

## What the research says (September 2026)

- Google: no special files or markup are needed for AI Overviews / AI Mode. A page must be indexed and snippet-eligible; classic SEO fundamentals apply. Google ignores `llms.txt`. Structured data should match visible content. `max-snippet`/`nosnippet` controls apply to AI features too.
- OpenAI: allow `OAI-SearchBot` to appear in ChatGPT search. `GPTBot` is training only.
- Anthropic: `Claude-SearchBot` (search index), `Claude-User` (user fetches), `ClaudeBot` (training). All honour robots.txt.
- Perplexity: `PerplexityBot` must be allowed; it is the one engine that reads `llms.txt`.
- Bing: standard SEO plus Article schema; IndexNow optional.
- GEO content studies: answer-first paragraphs, strict heading hierarchy, named author and dates, key-takeaways and FAQ blocks, no placeholder or invented facts. Citations concentrate in the first third of a page.
- Google sitemaps: `lastmod` is used when accurate; `changefreq`/`priority` are ignored.
- Google JavaScript SEO: an SPA should add `noindex` (or redirect to a real 404) for unknown routes to avoid soft 404s.

## Audit findings on the current site

- Per-route title/description/canonical/og already exist; JSON-LD is a single site-wide `Person` block in `public/index.html`; sitemap has no `lastmod`.
- Home has three `<h1>`; `/projects` and both project pages have none; section titles are `<div>`s.
- Articles use `<p><strong>` pseudo-headings, start with a duplicate "Article Outline", hero images are `alt="article"` and named `article_img (n).jpg`; one article contains placeholder content ("XYZ Corporation").
- Seven project thumbnails have no `alt`; the hero and sidebar images are oversized (sidebar icons are 230-280 KB PNGs shown at 20 px).
- Unknown URLs return HTTP 200 with the React Router default error page (soft 404). `/projects/` and `/projects` both return 200.
- Main JS bundle is 1.9 MB, mostly three.js for a decorative globe.
- Fonts load without `font-display`. `<html lang>` never changes when the language switcher is used.

## Design

### Single source of truth: `src/seo.js`

`pageMeta` grows per route: `type` (`profile`, `collection`, `project`, `article`), `headline` (visible H1), `image` (`src`, `width`, `height`, `alt`), `datePublished`, `dateModified`, `keywords`. `PERSON` and `ORGANIZATION` constants hold the entity facts that appear on the home page. The prerender step, the `<Seo>` component, the articles index, and the RSS/llms.txt generators all read from here.

### `src/structuredData.js`

`buildJsonLd(path)` returns one `@graph` per route: `WebSite`, `Person`, `Organization` on every page; `ProfilePage` on `/`; `CollectionPage` + `ItemList` on `/projects` and `/articles`; `BlogPosting` on articles; `WebPage` + `CreativeWork` on project pages; `BreadcrumbList` on every inner page. Dates are `YYYY-MM-DD`.

### `<Seo>` component

Renders title, description, robots (`max-image-preview:large`), canonical, Open Graph (type, site_name, locale, image with size and alt, article dates and tags), Twitter card tags, and the JSON-LD script. All OG/JSON-LD tags leave `public/index.html`. `src/ssr.js` adds Helmet script tags to the prerendered head.

### Content structure

- One `<h1>` per page. Home section titles become `<h2 class="title h-plain">` (the `.h-plain` utility keeps the div's look). Card titles become `<h3>`.
- Articles use a shared `ArticleLayout`: breadcrumbs, `<h1>` from `headline`, a byline with author link and `<time>` published/updated, the hero image with descriptive alt and dimensions. Article bodies get real `<h2>/<h3>` sections, a "Key takeaways" block at the top, an FAQ section with `<h3>` questions at the end, and no outline duplicate or placeholder content. No facts or statistics are invented.
- Project pages get `<h1>`, `<h2>` sections, breadcrumbs, alt text, and typo fixes.
- A `NotFound` route (`*`) renders a real not-found page with `noindex`. The prerender also writes it to `build/404.html`, and `vercel.json` rewrites unknown URLs to that file so non-JavaScript crawlers never receive the home page at a wrong URL (the Vercel CRA preset still answers with HTTP 200). Routes are case-sensitive, so `/Projects` is a not-found page rather than a duplicate of `/projects`.

### Crawl and discovery files (generated by `scripts/prerender.mjs`)

`sitemap.xml` with `lastmod`; `feed.xml` (RSS 2.0 of the articles, linked from `<head>`); `llms.txt` per the llmstxt.org format. `public/robots.txt` explicitly allows the major search and AI crawlers. `vercel.json` sets `trailingSlash: false` and cache headers for images.

### Build-time checks

The prerender fails the build if any route lacks metadata, has duplicate titles/descriptions, renders zero or more than one `<h1>`, has an `<img>` without `alt`, or emits JSON-LD that does not parse. It warns on long titles/descriptions.

### Performance

The three.js globe is code-split with `React.lazy`; article and oversized images are resized/recompressed; fonts get `font-display: swap`; below-the-fold images are lazy-loaded; `<html lang>` follows the i18n language.

## Out of scope (recommended follow-ups)

- A visible FAQ / services section on the home page in all three languages.
- URL-based localisation with `hreflang` (the site switches language client-side only).
- Search Console / Bing Webmaster verification and IndexNow submission.
- A `www` DNS record (currently does not resolve).

## Assumptions

- Article "Published on" dates shown on `/articles` are the true publication dates.
- Public facts used in structured data are the ones already visible on the site (Pitești, ARCHDEVS SRL, Politehnica University of Bucharest, listed skills, public email).
- The user wants maximum exposure to AI crawlers, including training crawlers.
